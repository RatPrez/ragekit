# RPF archives

`rpf.h` reads and writes GTA V's `.rpf` archives (RPF7): directories, binary files and resource files; the entry table
and names encrypted with AES or NG or not at all; files deflated and/or encrypted; archives nested in archives (a
`dlc.rpf` is full of them).

## Reading

```cpp
Rpf dlc = Rpf::open("update/x64/dlcpacks/mpheist/dlc.rpf");
for (int i : dlc.children(dlc.find("x64/levels"))) { const RpfEntry& e = dlc.entries()[i]; }
auto loc = dlc.resolve("x64/anim/cutscene/cuts_heist_int.rpf/heist_int-0.ycd");   // walks into nested archives
Bytes file = loc.archive->extract(loc.entry);    // a resource comes back as a complete RSC7 file
```

`extract` returns a binary entry decrypted and inflated, and a resource entry as a **complete RSC7 file**: the 16-byte
header rebuilt from the entry's page flags, then the deflate stream, which every reader in the library takes.
(CodeWalker's `ExtractFile` returns the inflated body without the header.) Retail archives keep scrambled bytes where
the header would be, so the header is always rebuilt from the table; archives made by FiveM and OpenIV, which keep a
real header, agree with it.

## Keys

Archives with encryption `none` or `OPEN` (most mod `dlc.rpf` files) open without keys. The game's own archives are NG
(most) or AES encrypted, and the key material comes from your copy of the game. **It is never committed and must not
be.** It lives in `%USERPROFILE%\.ragekit\keys` (`RpfKeys::default_folder()`) under CodeWalker's cache file names:

| file | content |
|---|---|
| `gtav_aes_key.dat` | the AES-256 key, 32 bytes |
| `gtav_ng_key.dat` | 101 NG keys, 272 bytes each |
| `gtav_ng_decrypt_tables.dat` | 17 rounds x 16 x 256 little endian words |
| `gtav_hash_lut.dat` | the 256-byte table of the file name hash that picks the NG key |

`rk rpf keys <GTA5.exe> --magic <magic.dat>` creates them: it finds the AES key and the hash table in the executable by
their SHA1 hashes (`src/rpf_key_hashes.inc`, generated by `tools/gen_rpf_hashes.py`; a few seconds), then decodes the NG
keys and tables from CodeWalker's `magic.dat` (`CodeWalker.Core/Resources/magic.dat`, itself encrypted with the AES
key), because current executables no longer contain them. Key files made by CodeWalker (`GTA5Keys.SaveToPath`) can
simply be copied into the folder. `Rpf::open(path, keys)` takes an `RpfKeys` object for other locations.

## Writing

`RpfBuilder` builds an archive from a tree and writes the whole file; there is no patching in place. Add, replace,
rename and remove entries, then `build()` (bytes) or `save(path)`.

```cpp
RpfBuilder b;                                          // or RpfBuilder::from_archive(Rpf::open("dlc.rpf"))
b.add_file("stream/prop.ydr", rsc::read_file("prop.ydr"));   // RSC7 data becomes a resource entry, the rest deflated binaries
b.add_binary("common/data/x.meta", xml_bytes);
RpfBuilder inner; inner.add_file("a.txt", text);
b.add_archive("dlc/child.rpf", std::move(inner));      // a nested archive
b.rename("stream/prop.ydr", "prop2.ydr"); b.remove("common");
b.save("out.rpf");                                     // RpfWriteOptions: encryption None, Open (default) or Aes; compress
```

- A resource is given as a complete RSC7 file: its 16-byte header stays in the archive as it is (a real header, as
  OpenIV and FiveM write) and its page flags go into the entry. Resources of 0xFFFFFF bytes or more get the scrambled
  size.
- `from_archive` copies entries lazily and without recompressing (`Rpf::extract_stored`), NG archives included, so a
  retail archive can be written back as an OPEN one. Nested archives that are not encrypted are copied byte for byte;
  encrypted ones (and all of them with `Nested::Rewrite`, which makes them editable through `nested(path)`) are
  rebuilt. `.ysc` resources stay encrypted as they were.
- Layout: the header, the entry table and the names padded to 512-byte blocks. A directory's children are contiguous
  and sorted by name (ordinal); directories get their children in depth-first preorder, as retail archives do; names
  are shared; files follow in table order, each padded to a block.
- Encryption: OPEN (the default), none, or AES for the tables (the files stay plain). NG archives cannot be written yet.

## The rk commands

```
rk rpf ls <file.rpf> [path] [-r] [--nested] [--tsv [--hash]]   the path may pass through nested archives
rk rpf cat <file.rpf> <entry path> <out>
rk rpf extract <file.rpf> <out dir> [path] [--nested]           --nested also unpacks nested archives into folders
rk rpf keys <GTA5.exe> [key folder] [--magic <magic.dat>]
rk rpf pack <dir> <out.rpf> [--aes]                             a folder into an archive; *.rpf folders become nested archives
rk rpf add <rpf> <entry path> <file>                            the path may pass through nested archives
rk rpf rm <rpf> <entry path>
rk rpf rewrite <in.rpf> <out.rpf> [--aes] [--nested]            any archive (NG too) as OPEN or AES
```

`add` and `rm` rewrite the file through `<rpf>.tmp` and refuse NG archives (rewrite them first).
